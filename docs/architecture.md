# 架构与代码规范

UI、板卡和 BLE 依赖可移植应用端口；`main` 只组装依赖。使用 C++17、组合与依赖注入，避免型号工厂和不必要继承层。

- `remote_core` 不依赖 ESP-IDF、FreeRTOS、NimBLE 或 LVGL。`Controller` 根据传入时间推进拍摄状态，消费异步完成事件；取消代次和操作 ID 防止旧完成恢复已取消拍摄。
- `ICameraAdapter` 是应用端口。请求返回 Ok 表示接受，拍摄完成通过带会话／操作 ID 的事件通知；Ready 保证握手、必要订阅、快门权限、中性释放和首次存储成功。
- `fuji::Session` 和协议解析可在主机运行。Basic／Secure 使用共享会话与不同握手步骤；依赖 `ILink` 与 `IStore`。广播解析、握手顺序、取消和重试在这里测试。
- `Xe5Camera` 将可移植会话连接到 NimBLE host 异步 GAP/GATT 和 NVS。动态发现服务、特征及 CCCD；缓存句柄仅用于当前链路。BLE 回调仅复制固定长度事件，协议决策与全部发送在唯一 owner 任务执行。
- `app_runtime` 轮询 BOOT、处理输入和取消，再消费相机事件并发布可平凡复制的 Snapshot。UI 只能提交意图，不能直接访问相机或 NVS；BLE 回调不能访问 LVGL。
- 普通输入携带取消代次。取消和主动断开使用原子标记，不受输入队列满影响；旧输入丢弃。BLE 队列溢出使会话失效并断开。释放使用独立待处理槽，优先于未发送拍摄参数。
- LVGL 只在 UI 任务访问。颜色、字体、按钮与连接覆盖页复用同一套构造方法；设计图片是参考，生产界面由原生控件绘制。

新增相机协议时实现应用端口并复用输入控制器，不让 UUID 或厂商字段进入核心。未知能力不可用，没有反馈的数据保持未知。

运行 `python tools/project.py test` 与 `format-check`。固件使用精确 IDF 5.5.3。界面输入与视觉检查运行 `preview`；中文文案修改后使用锁定生成器与输入字体重新生成。不得提交 SDK、工具链、构建产物、密钥或包含设备隐私的日志。
