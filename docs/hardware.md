# 硬件、刷机与故障排查

目标是 **ESP32-S3-Touch-AMOLED-1.43C**，不是不带 C 后缀的 1.43。参考 [Waveshare 官方示例](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.43C/tree/8cea11ddae6167dd591d1f5465fd7b615080360f/examples/esp-idf/06_LVGL_V9_Test)。

| 功能 | 配置 |
| --- | --- |
| Flash / PSRAM | 8MB QIO / 8MB Octal 80MHz |
| 圆屏 | 466×466，CO5300，QSPI 40MHz |
| LCD 数据 D0–D3 | GPIO9、10、11、12 |
| LCD CS / CLK / RESET | GPIO15 / 14 / 13 |
| LCD TE | GPIO8，当前不启用 TE 同步 |
| CST820 SDA / SCL | GPIO47 / 48，地址 0x15 |
| 触摸 RESET / INT | GPIO16 / 17；当前轮询触摸 |
| 电池 ADC | GPIO4，ADC1 channel3，电压分压 ×2 |
| 充电状态 | GPIO7，低电平表示正在充电 |
| BOOT | GPIO0，低有效，25ms 去抖 |
| 共享 I2C 上音频芯片的供电 / 功放控制 | GPIO18 保持高电平 / GPIO46 仅播放期间拉高 |
| ES8311 I2S MCLK / BCLK / WS / DOUT | GPIO38 / 39 / 40 / 41；I2S0，16kHz、16bit 双声道 |

CO5300 使用官方例程的 SH8601 兼容 QSPI 驱动及专用初始化序列和 X 偏移 8，不能替换成其他板卡的默认配置。显示使用两个内部 DMA 分块缓冲，不分配完整双帧缓冲；RGB565 在发送前交换字节。触摸坐标翻转并限制在 0–465。

触摸与 ES8311／ES7210 共用 I2C。根据[官方原理图](https://files.waveshare.com/wiki/ESP32-S3-Touch-AMOLED-1.43C/ESP32-S3-Touch-AMOLED-1.43C-Schematic.pdf)，GPIO18 控制音频芯片电源；即使不使用音频也必须保留该供电，防止未供电的器件影响共享总线。实机对照：GPIO18 低时触摸初始化与轮询持续返回 `ESP_ERR_INVALID_STATE`；改为高、保持 GPIO46 低后，`0x15` 地址探测、芯片编号及触摸采样均成功。该历史实测未启用音频；本次新增音频与触摸共存仍需复测。

快门音效依据同一固定提交的 [04_Audio_Test 板卡配置](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.43C/blob/8cea11ddae6167dd591d1f5465fd7b615080360f/examples/esp-idf/04_Audio_Test/components/externlib/codec_board/board_cfg.txt)，使用固定版本 `esp_codec_dev 1.5.8` 驱动 ES8311 DAC，复用已有 I2C 总线，不启用 ES7210 录音。音效为代码合成的原创双击声，不包含外部音频文件。独立 `shutter_audio` 任务以 10ms 分块写入 PCM，每次写入最多等待 40ms，播放结束等待 DMA 尾部后关闭功放；空闲时功放关闭，I2S 仍输出静音时钟。音效请求不等待、不排队，与相机连接状态及输入取消队列独立。它仅表示已按下本地快门，不是合焦、曝光或命令成功回执；按下后滑动取消也不会撤销已播放的声音。

触摸当前采用轮询，复位后向 CST8xx 的 `DisAutoSleep`（`0xFE`）写入非零值，避免自动待机影响空闲与松手采样；这会增加触摸芯片的待机功耗，屏幕调暗／熄屏不代表触摸芯片休眠。寄存器含义可参考 [CST8xx 驱动](https://github.com/zephyrproject-rtos/zephyr/blob/main/drivers/input/input_cst8xx.c)与[板厂寄存器说明](https://files.waveshare.com/upload/c/c2/CST816S_register_declaration.pdf)。启动日志输出 `触摸地址0x15`、芯片／项目／固件编号及配置写入结果；编号取自设备，不预设已验证型号。空闲读取失败不会吞掉下一次新触摸；按住期间失败仍取消当前操作，直至有效松手后才接受新触摸。

USB 数据线连接板卡 Type-C 即可刷写，不需要外接快门线。电池需使用板卡要求的 3.7V 单节锂电接口并核对极性。软件不接管 PWR 硬件按键。BOOT 上电时保持按住可能进入下载模式；应用启动后也会忽略已按住的 BOOT，直到释放。

电量是校准 ADC 的电压估算，并非库仑计：16 次平均后再进行时间滤波。充电时端电压会影响百分比；GPIO7 高只说明“未在充电”，不能推断电池已满或 USB 未连接。本板未提供可靠的电池存在检测，因此 USB 单独供电时，即使 ADC 落入合理区间也不能证明电池存在；不据此报告“已安装电池”。电压无效或校准失败时显示未知。

## 常见问题

- 无串口：更换确认可传数据的 USB 线；依照板卡说明按住 BOOT，再操作 PWR 进入下载模式；检查设备管理器／`ls /dev/cu.*`／`ls /dev/ttyACM*`。Linux 检查当前用户是否有串口组权限，重新登录后生效。
- 黑屏：先点击唤醒；检查是否刷错非 C 版固件、PSRAM 配置、显示初始化或供电。串口日志中的 panic 应先解决，不反复擦除配对数据。
- 颜色或触摸方向错误：检查 RGB565 字节序、屏幕旋转与坐标翻转；修改板卡适配，不能在业务层添加偏移补丁。
- 点击和滑动均无反应：检查启动时 `触摸地址0x15轮询配置失败`／`读取触摸地址0x15设备信息失败` 及运行中的 `触摸读取失败` 日志；持续读取失败每 5 秒记录一次。正常按下／松手会打印 `触摸按下`／`触摸松开` 和原始／UI 坐标；超界会打印 `触摸坐标超界`。请保留启动日志与一次操作的日志，用于区分 I2C 通信、坐标和 UI 问题，不擦除 NVS 排查触摸。
- `ESP_ERR_INVALID_STATE` 持续出现：先确认 GPIO18 维持高电平，再检查 `Touch bus idle levels` 的 SDA／SCL 是否均为 1，以及 `Touch address probe at 0x15` 的结果。不要只调整手势阈值或清除配对记录。
- 编译器缺失：运行 `setup`；GitHub 下载中断时可再次运行，SDK 和下载缓存可复用。
- SDK 版本错误：新终端中指定本项目 `.tools/esp-idf`，不要加载全局其他版本的 IDF 环境。
- NVS 损坏：程序会报错，避免静默删除配对。确认不需要旧数据后，使用单独的 `erase --confirm-erase` 再刷写。
- 显示“协议待验证”：当前版本的预期行为，不能通过反复配对解决；缺项见协议文档。

## 执行日志

项目运行日志使用 UTF-8 简体中文，状态、操作与字段说明均使用中文；保留模块标签、错误符号、错误编号、硬件引脚及协议标识，便于定位源代码。ESP-IDF、NimBLE 等第三方组件日志保留上游原文，不修改 SDK。串口日志不由 LVGL 绘制，不占用屏幕字库字形。

开发固件在默认 INFO 级别输出执行路径，前缀为时间戳、等级和模块名：

| 模块 | 记录内容 |
| --- | --- |
| `startup` | NVS、板卡、owner／UI 任务启动顺序与完成状态 |
| `board` | 引脚与供电、触摸复位／地址探测／寄存器回读、原始与翻转坐标、首帧传输、亮度、ADC 校准 |
| `ui` | 首次 LVGL／输入回调、手势起止／位移、唤醒吞输入、取消原因、横滑、页面切换、按钮和弹窗 |
| `runtime` | 输入入队／分发／过期丢弃、队列满取消、取消代次、BOOT 去抖、连接／拍摄／提示／电源状态变化 |
| `camera` | 配对存储读取结果、协议门槛、owner 中处理的 BLE 事件、握手步骤、指令返回值与故障原因 |
| `fujifilm` | 相机记录读写／提交结果、重启恢复的绑定数量、当前对端 LTK／IRK 是否存在、安全认证结果与再次要求数字确认 |
| `audio` | 音效初始化结果及 I2S 播放故障；失败时关闭功放，保留界面与相机任务运行 |

触摸统计每 5 秒记录读取数、错误总数、最后一次 I2C 结果、触点／事件／坐标及 SDA／SCL／INT 电平。I2C 失败时数据缓冲无效，不能将该行的零坐标视作有效采样。UI 与 owner 每 10 秒各输出一次心跳；前者包含输入回调和显示完成次数，后者包含队列深度、内部堆最小余量、owner 栈最小余量（字节）与电池读数。手指持续按下的坐标记录间隔至少 150ms，状态只在变化时输出，不逐个打印 5ms owner 循环。

一次正常触摸可依次追踪 `触摸按下`、`手势开始`、`输入已入队`、`分发输入` 和 `手势结束`。横滑会出现 `左右滑动` 与 `页面切换`。不同 CPU 上的日志可能交错，取消通过日志中的 `代次` 关联；读取出错或队列满仍走原有取消路径，BLE 回调仍只投递事件，日志在 owner 中处理事件时输出。相机协议未验证时，只能验证交互，不会产生拍摄／广播。日志不打印 BLE 密钥、握手载荷或完整对端身份。

使用 `./project.sh monitor --port <串口>` 查看，`Ctrl+]` 退出。监视器启动会复位开发板，重现启动路径；刷写前先退出占用同一串口的监视器。本地采集记录放在被忽略的 `build/log/` 中，不随源码提交。

`camera_owner` 使用 12 KiB 任务栈，覆盖安全确认后嵌套调用 NimBLE GATT 与日志的开销。读取会话代次、配对保存状态时使用标量访问接口，不临时复制包含 16 个候选项的 `LinkSnapshot`；发布快照时直接写入已有缓冲。`app_runtime` 与 `camera_ble` 构建生成 `.su` 栈占用报告，单函数栈帧超过 2048 字节会编译失败。这是单函数检查，整条调用链的峰值仍须通过实机 owner 心跳中的 `栈最小余量字节` 验证。

重启后再次出现验证码时，先区分相机记录与 BLE 绑定：`已保存相机=1` 仅表示恢复了相机记录，不保证当前连接能匹配到绑定密钥。查看 `绑定检查` 的 `启动恢复相机` 与 `认证前` 两个阶段：`查询返回码=0 LTK存在=1` 表示 host 绑定库中存在对应 LTK；`查询返回码=5` 表示未找到记录。再结合 `安全认证完成` 的结果与 `安全交互请求` 判断安全建立过程。日志只输出数量、返回码和存在标志，不输出地址、验证码或密钥；这些诊断不会清空或修复绑定，也不会自动确认验证码。
